# Косоглазие: прототип M3.4

M0: камера → MediaPipe Face Landmarker → контуры и числа радужек, режим `isDev`.
M1: масштаб (размер радужки), личная модель лица, поза, угол каждого глаза, личный ноль, вергенция в ПД; тесты на синтетике (`src/core/`, `tests/`).
M2: расстояние по известному размеру (поле зрения камеры), размер экрана и коэффициенты глаз по сетке 3×3 (вошли в единый мастер). M3: детектор срыва, замер «срыв при отдалении», упражнение 1, сессия «до → упражнение → после».
Следующие этапы (M4+) не начаты.

## Запуск
```
npm install        # создаст package-lock.json, его нужно закоммитить (CI использует npm ci)
npm run typecheck
npm test           # тесты математики на синтетических данных
npm run build      # esbuild → dist/; скачает модель face_landmarker.task в .cache/
npm run serve      # http://localhost:8080
```
Android: USB + `chrome://inspect`, проброс порта 8080 (камере нужен localhost или HTTPS) либо деплой на GitHub Pages.

## Деплой
Push в `main` → `.github/workflows/deploy.yml` (npm ci, сборка, официальные Pages-действия). В настройках репозитория: Pages → Source: GitHub Actions.

## Проверка M0 (главный риск плана)
1. Несколько людей без косоглазия: числа стабильны? Шум dx/dy в состоянии покоя (± в панели).
2. Сильно отклонённый глаз: окно «глаза» (кропы) показывает, лежит ли метка радужки на реальной радужке или «тянется» к типичному положению.
3. Сцены с меткой в CSV: «оба открыты», «правый закрыт», «левый закрыт», «срыв». Запись → CSV (только числа).

Соглашения: dx > 0 в сторону носа для обоих глаз, dy > 0 вверх; правый/левый по человеку; зеркалится только превью.
Вергенция (сведение/разведение) = R_dx + L_dx; версия (общий поворот взгляда) = R_dx − L_dx.

## Калибровка (единый мастер)
Меню ☰ → «Калибровка». Пять шагов; каждый объясняет, что даёт, имеет кнопку «Начать», таймер 3 с до старта и автостоп. Рамка по краю экрана: красная идёт запись, зелёная закончено. Звука и вибрации нет. Кнопка «Пропустить» есть, только если значение уже записано (или шаг по желанию).

| Шаг | Что даёт | Как часто | Хранится | Пропуск |
| --- | --- | --- | --- | --- |
| 1. Размер радужки (11,7 мм, ввод или карта у щеки) | пиксели в миллиметры | один раз на человека | localStorage | если записан |
| 2. Расстояние до камеры (лист A4 29,7 см или линейка) | поле зрения камеры: расстояния в см | один раз на камеру и разрешение | localStorage | если записано |
| 3. Модель лица (10 с поворотов головы) | поза головы и масштаб в каждом кадре | один раз на человека и камеру | localStorage | если есть, камера та же, поле зрения то же |
| 4. Ноль (оба глаза в камеру, 6 с) | точка отсчёта отклонения | в начале каждой сессии | только память страницы | если задан в этой сессии |
| 5. Уточнение углов (по желанию): размер экрана по карте + сетка 3×3 каждым глазом | коэффициенты глаз: углы в градусах точнее | на устройство, редко | localStorage | всегда (углы тогда ориентировочные) |

Расстояние в шаге 2 считается до плоскости глаз (скула рядом с глазом), не до носа: нос ближе к экрану. Размер экрана (шаг 5) нужен только для сетки, к расстоянию не относится.
Журнал CSV один: при запуске мастера очищается; сцены (`iris_card`, `distance`, `face_model`, `zero`, `grid_right`, `grid_left`) ставятся автоматически. Скачать: меню → «Скачать CSV калибровки». «Разработка» в меню: isDev, разрешение, направление срыва, запись сцены с меткой (`dev:метка`), снимок.

## Замер и тренировка (M3)
Меню → «Замер срыва (3 попытки)» или «Тренировка (сессия)». Нужны калибровка и ноль в этой сессии. Первый раз показывается предупреждение о противопоказаниях. Попытка: 3 с до старта, красная рамка до срыва и возврата (не дольше 30 с), результат в см. Порог срыва: не меньше 3° и 3σ шума нуля. Сессия: замер «до» (3) → упражнение 1 (5) → замер «после» (3). В CSV столбцы `dev_inst` и `event` (`break`, `return`, `mark`).

## Что изменилось в M3.1 (по итогам живой проверки)
- **Размер радужки по карте**: добавлена поправка на глубину 12 мм (карта у щеки лежит глубже радужки, без поправки значение завышалось на 5-6 %: 13,1 мм против 12,35 мм по заключению врача). Значение также можно ввести вручную.
- **Расстояние**: можно ввести поле зрения вручную (прямо или по диагонали из паспорта); новое меню «Проверка расстояния» (линейка/A4) показывает ошибку и подгоняет поправку; расстояние для срыва и возврата сглажено медианой по 7 кадрам. В панели разработчика рядом видно расстояние по модели лица и только по радужке.
- **Стартовое окно камеры**: при запуске, если разрешение уже выдано, камера включается сама; иначе показывается окно с объяснением и кнопкой «Включить». Кнопки «Включить камеру» на экране больше нет.
- **Попытка = цикл «срыв — возврат»**: кнопка «Я заметил срыв» меняет цвет, запоминает расстояние и превращается в «Глаз собрался»; камера и ваши отметки пишутся отдельно, граница = середина между срывом и возвратом. Окно ожидания возврата 20 с, порог возврата 0,6·T (раньше 0,5·T и 0,8 с), есть кнопка «Закончить попытку».
- Итоги замеров сохраняются (localStorage, до M4) и сравниваются с прошлым разом.

## Что изменилось в M3.2
- **Упражнение «Удержание на границе»** (`src/core/hold.ts` логика, `src/exercise.ts` экран): приложение командует «занимайте позицию, держите, чуть ближе/дальше, срыв: приблизьте». Удержали 20 с подряд: ступень дальше (+2 см или 3 %); два ранних срыва: ступень назад; три срыва за 30 с на самой лёгкой ступени: остановка. 3 минуты. Сессия теперь: замер «до» → удержание → замер «после». Отдельный запуск: меню → «Удержание на границе» (по последнему замеру).
- **Мишень**: буква на чёрном фоне у верхнего края (рядом с камерой), меняется раз в 6 с; три размера (угловая высота 7,5′ / 15′ / 30′), опция постоянного углового размера. Физический размер зависит от калибровки экрана (шаг 5 мастера), иначе грубая оценка.
- **Касание экрана в любом месте и пробел** отмечают срыв и возврат (в замере и в упражнении); кнопка срыва убрана. Касания до старта записи не считаются.
- **Без нижнего окна**: замеры, упражнение и проверка расстояния идут страницами во весь экран; превью не рисуется, пока страница открыта. Нижняя панель осталась только у калибровки (там нужно видеть себя).
- Расстояние `zq` (медиана 3 кадров) для подсказок упражнения, `zs` (7 кадров) для записи результатов.
- Тесты: `tests/hold.test.ts` (лестница, срывы, потеря лица, пределы, направление «приближение»).

## Что изменилось в M3.3
- **Ноль вынесен из калибровки** (`src/zero.ts`): пункт меню «Ноль (в начале сессии)». Мастер калибровки теперь из 4 шагов. Замер, тренировка и удержание сами проверяют ноль: нет или старше 3 часов (`ZERO_FRESH_H`) значит экран с кнопкой «Пройти ноль», после него возврат на тот же экран. Нет калибровки: кнопка «Открыть калибровку».
- **Без всплывающего окна**: калибровка идёт на странице под видео (видео нужно, чтобы видеть себя), остальное на страницах во весь экран; сверху заголовок раздела.
- **Таймеры вернулись**: в CSS у `#timer` второй `z-index:5` перебивал `2100`, и страница закрывала таймер.
- **Срыв в замере = удержание касания** (или пробела): нажатие даёт расстояние срыва, отпускание расстояние возврата; после отпускания попытка ждёт 2,5 с. Ручная отметка пока приоритетнее камерной. Экран сообщает, если камера срыв не увидела.
- **Журнал CSV**: новые столбцы `user_hold` (касание держится) и `det_state` (детектор камеры считает срыв), по кадрам. CSV скачивается с экрана результатов замера и из меню.

## Что изменилось в M3.4 (разбор журнала замера 24.11)
- **Новый детектор срыва** (`src/core/windowDetector.ts`): медиана за окно 1 с против базы попытки (слитые кадры за предыдущие 5 с), порог 5°. Прежний (по кадру, порог не меньше 3σ шума от нуля = 11,6°) не срабатывал. Тесты прогоняют реальные данные журнала (`tests/fixtures/measure-2026-11-24.json`) и синтетику (ложные срывы < 5 % прогонов по 30 с).
- **Реакция человека**: нажатие пересчитывается на момент за 1,5 с до него (по истории расстояний); после попытки показывается сверка «камера / вы нажали / через сколько секунд». Приоритет: камера, иначе нажатие с поправкой; возврат по отпусканию.
- **Проверка нуля**: вместо недостижимого «разброс < 1,5°» показываются шум кадра и ошибка нуля; предупреждение, если ошибка нуля > 1,2° или половины записи расходятся > 4°. Запись 8 с.
- Упражнение «удержание» тоже использует новый детектор (касание синхронизирует его через `forceBroken` / `forceFused`).
